# 组题以题组表为单位（每题都归组，共享内容集中存）

306 含 A3/A4 病例串与 B 型共用选项池，需要"共享内容展示一次 + 子题连续"的块状呈现，且组卷要按块取题。早期方案在 `questions` 加 `series` 分组标记 + `scenario` 列、共享内容逐子题重复存（存储冗余为明确取舍，2026-08-04 曾落地两列）。落地时暴露出三点真实代价，改为题组表。

Status: accepted（2026-08-04，取代 ADR 0003 中"不建组表"的存储方案）

**决策核心**:
- 新增 **`question_groups` 题组表**：`kind`（`single` / `case`(A3/A4) / `pool`(B型)）+ 共享内容（`scenario` 病例、`options` 选项池）；**每题都归组**——独立题组 1:1、病例/池子题 1:N。
- `questions` 移除 `scenario` / `series`，改挂 **`group_id`（非空 FK）** + **`position`**（组内显式顺序）；`options` 改可空（B 型子题取组的池）。
- **判分/薄弱点/错题仍按小题**（`answer_records` 一行一题，每个子题独立判分、独立归主考点）；题组只承担**抽取/展示/顺序**，不参与判分。
- **组卷**：按整块取题（抽到任一字题即拉整个题组）、组内按 `position` 排序、**按小题计数**、整块必进宁多勿拆（不拆散病例/池）。

**考虑过的方案**:
- **`series` + `scenario` 逐题重复（原方案，已落地又撤）**：否决——共享内容逐子题重复，内容生产是「AI 起草 → 人工审校 → 反复修订」，改病例/池要同步 N 行，漏改即块内矛盾；`series` 是松散字符串，无引用完整性，块删除/替换无原子单位。
- **题组只做排序容器、共享内容仍逐题重复**：否决——题组表失去"集中存共享内容"的核心价值，编辑同步问题原样保留。
- **组内顺序按题目 id 递增**：否决——子题删除后重插会拿新 id，按 id 排序会把 A3/A4 临床顺序（诊断→检查→治疗）打乱；`position` 显式排序不受编辑影响。

**连带结果 / 行动项**:
- 迁移 `backend/migrate_groups.py`（幂等）：建 `question_groups` 表；`questions` 加 `group_id`/`position`、`options` 改可空；为现有独立题各建一个 `single` 空壳题组回填 `group_id`；删 `scenario`/`series` 两列。
- 内容工具链（`import_questions.py` / `generate_questions.py`）改按「先建题组 → 再落子题」输出。
- 前端块状渲染：共享内容取题组、子题按 `position` 连续排列。
- 判分语义不变：`a`/`b` 单选、`x` 多选（见 ADR 0003）。
